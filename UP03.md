# UP3: Depuración de código con IntelliJ IDEA

Todo entorno de desarrollo, independientemente de la plataforma, así como del lenguaje de programación utilizado, suministra una serie de herramientas de depuración, que nos permiten verificar el código generado, ayudándonos a realizar pruebas tanto estructurales como funcionales.

Durante el proceso de desarrollo de software, se pueden producir dos tipos de errores: **errores de compilación** o **errores lógicos**.

Cuando se desarrolla una aplicación en un IDE, ya sea IntelliJ IDEA, Eclipse o Netbeans, si al escribir una sentencia, olvidamos un ";", hacemos referencia a una variable inexistente o utilizamos una sentencia incorrecta, se produce un error de compilación. Cuando ocurre un error de compilación, el entorno nos proporciona información de donde se produce y como poder solucionarlo. El programa no puede compilarse hasta que el programador o programadora no corrija ese error.

El otro tipo de **errores son lógicos**, comúnmente llamados *bugs*, estos no evitan que el programa se pueda compilar con éxito, ya que no hay errores sintácticos, ni se utilizan variables no declaradas, etc. Sin embargo, los errores lógicos, pueden provocar que el programa devuelva resultados erróneos, **que no sean los esperados** o pueden provocar que el programa termine antes de tiempo o no termine nunca.

Para solucionar este tipo de problemas, los entornos de desarrollo incorporan una herramienta conocida como **depurador**. El depurador permite supervisar la ejecución de los programas, para localizar y eliminar los errores lógicos. Un programa debe compilarse con éxito para poder utilizarlo en el depurador.

El depurador nos permite analizar todo el programa, mientras éste se ejecuta. Permite suspender la ejecución de un programa, examinar y establecer los valores de las variables, comprobar los valores devueltos por un determinado método, el resultado de una comparación lógica o relacional, etc.

## Puntos de ruptura

Los puntos de ruptura, similares a marcadores estratégicos, son herramientas fundamentales en el arsenal del desarrollador para realizar una depuración efectiva en cualquier IDE. Estos puntos permiten detener la ejecución de un programa en una línea o parte específica del código, ofreciendo un control preciso sobre el flujo de la aplicación.

A continuación, exploraremos cómo utilizar los puntos de ruptura de manera eficiente en el entorno de desarrollo de IntelliJ IDEA:

* **Establecimiento de Puntos de Ruptura**: Similar a la colocación de marcadores, los puntos de ruptura se establecen fácilmente haciendo doble clic sobre el número de línea correspondiente en el código fuente. Este sencillo acto marca el lugar exacto donde se detendrá la ejecución del programa.

* **Análisis Detenido del Programa**: Una vez que el programa se detiene en un punto de ruptura, se abre un abanico de posibilidades para el análisis detenido. Los desarrolladores pueden examinar el valor de cualquier variable o propiedad en ese momento específico, proporcionando una visión instantánea del estado interno del programa.

* **Evaluación de Expresiones**: Los puntos de ruptura permiten analizar el valor de expresiones en tiempo real. Esto significa que los desarrolladores pueden evaluar y comprender el resultado de expresiones complejas o cálculos en el contexto actual de la ejecución.

* **Ejecución Línea a Línea**: Con la ejecución paso a paso (F7), los desarrolladores pueden avanzar línea a línea a través del código, verificando el flujo de la aplicación y asegurándose de que cada instrucción se ejecute según lo previsto.

* **Opciones de Detención o Continuación**: Después de realizar las comprobaciones necesarias, los desarrolladores tienen la libertad de decidir los siguientes pasos. Pueden optar por detener por completo la ejecución (CRL+F2) del programa, proporcionando un punto de intervención para posteriores ajustes, o continuar la ejecución (F9) hasta el final.

[cite_start]Estos puntos de ruptura no solo ofrecen control y visibilidad durante la depuración, sino que también agilizan el proceso de identificación y corrección de errores[cite: 39]. [cite_start]La capacidad de analizar el estado del programa en puntos cruciales, evaluar expresiones y verificar el flujo de ejecución, brinda a los desarrolladores un dominio completo sobre su código, mejorando la calidad y confiabilidad del software en desarrollo[cite: 40].

## Proceso de depuración con IntelliJ IDEA

[cite_start]El proceso de depuración en IntelliJ IDEA es una herramienta esencial para localizar y corregir problemas en el código de manera eficiente[cite: 82]. [cite_start]A continuación, describiremos un flujo de trabajo paso a paso utilizando los recursos clave del depurador de IntelliJ IDEA[cite: 83]:

1.  [cite_start]**Localizar el Problema**: Antes de iniciar el proceso de depuración, es crucial identificar el área del código que está generando el problema[cite: 84]. [cite_start]Esto puede basarse en mensajes de error, resultados inesperados o cualquier comportamiento no deseado[cite: 85].
2.  [cite_start]**Poner un Breakpoint en la Línea del Error o en la Entrada a la Llamada**: Una vez localizado el área problemática, establecer un punto de ruptura (breakpoint) en la línea específica donde se sospecha que ocurre el error o en la entrada a la llamada que está causando problemas[cite: 86]. [cite_start]Esto se logra haciendo clic en el margen izquierdo de la línea en cuestión[cite: 87].
3.  [cite_start]**Lanzar el Debug (MAY+F9) y Utilizar F8 (Step Over) o F7 (Step Into)**: Iniciar la depuración presionando "MAY+F9" o seleccionando "Debug" desde el menú de ejecución[cite: 88]. [cite_start]Luego, avanzar paso a paso utilizando "F8" (Step Over) para ejecutar la línea actual sin entrar en los métodos, o "F7" (Step Into) para ingresar a los métodos o funciones llamados[cite: 89].
4.  [cite_start]**Evaluar el Contenido de las Variables o Expresiones en Cada Paso**: Durante la ejecución paso a paso, utilizar la ventana del examinador de variables para evaluar el contenido de las variables o expresiones clave[cite: 90]. [cite_start]Esto [cite: 91] [cite_start]proporciona información valiosa sobre el estado interno del programa en cada punto de ejecución[cite: 92].
5.  [cite_start]**Una Vez Localizado el Error, Detener el Debug (CTRL + F2)**: En el momento en que se identifica y comprende el error, detener la ejecución del programa y el proceso de depuración utilizando "CTRL + F2"[cite: 93]. [cite_start]Esto permite finalizar la depuración de manera controlada y tomar medidas para corregir el código[cite: 94].

[cite_start]Siguiendo este proceso, los desarrolladores pueden de manera efectiva identificar, entender y corregir problemas en su código[cite: 95]. [cite_start]La combinación de puntos de ruptura estratégicos, la ejecución paso a paso y la evaluación de variables proporciona una visión detallada del flujo de ejecución, facilitando la resolución de problemas de manera rápida y precisa en IntelliJ IDEA[cite: 96].

## Configuración de breakpoint

[cite_start]La configuración de puntos de ruptura en IntelliJ IDEA proporciona una manera efectiva de personalizar la depuración de tu código, permitiéndote detenerte en momentos específicos y bajo condiciones particulares[cite: 98].

[cite_start]Para establecer un punto de ruptura abre el archivo fuente en el cual deseas configurar el punto de ruptura[cite: 99]. [cite_start]Puedes hacer clic en el margen izquierdo junto a la línea de código deseada o utilizar la combinación de teclas "CTRL + F8" para activar o desactivar un punto de ruptura en la línea actual[cite: 100].

[cite_start]Haz clic derecho en el punto de ruptura que has establecido y selecciona "More" en el menú contextual[cite: 101]. [cite_start]Esto abrirá la ventana de configuración del punto de ruptura[cite: 102].


[cite_start]En la ventana "Breakpoint Properties", tendrás la opción de establecer **condiciones adicionales** para el punto de ruptura[cite: 103]. [cite_start]Puedes especificar condiciones de expresiones que deben cumplirse para que el punto de ruptura se active[cite: 104].

[cite_start]Utiliza la opción "**Pass count**" para especificar cuántas veces debe ejecutarse el punto de ruptura antes de detener la ejecución, en otros entornos de desarrollo esta funcionalidad se conoce como *hit count*[cite: 105]. [cite_start]Esto es útil cuando deseas detenerte solo después de que una condición específica se haya cumplido un número determinado de veces[cite: 106].

[cite_start]En la configuración avanzada del punto de ruptura, puedes agregar acciones adicionales que se ejecutarán cuando se alcance el punto de ruptura[cite: 107]. [cite_start]Esto podría incluir la ejecución de scripts, comandos o incluso la modificación de variables en tiempo real[cite: 108].

[cite_start]Puedes configurar un breakpoint para detener la ejecución solo cuando se lanza una **excepción específica**[cite: 109]. [cite_start]Esto es útil para centrarse en situaciones excepcionales sin detenerse en cada línea de código[cite: 110].


[cite_start]La capacidad de configurar puntos de ruptura de manera flexible en IntelliJ IDEA te permite adaptar la depuración a tus necesidades específicas, lo que facilita la identificación y corrección de problemas en tu código de manera más eficiente[cite: 111].
