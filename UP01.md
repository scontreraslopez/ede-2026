## 0. PUNTO DE PARTIDA

Antes de empezar, comprobad estas cuatro ideas. No cuentan para la nota; sirven para saber qué necesitáis repasar:

1. ¿Es lo mismo una aplicación que el archivo que abrís con ella?
2. Si apagáis el ordenador, ¿se pierde todo lo guardado en el SSD?

4. ¿Java y IntelliJ IDEA son el mismo tipo de herramienta?

Si dudáis, esta tabla y los primeros apartados os ayudarán:

| Término | Significado y ejemplo |
|---|---|
| Archivo o fichero | Información guardada con un nombre: `notas.txt`. |
| Carpeta | Ubicación para organizar archivos y otras carpetas: `EDE`. |
| Extensión | Parte final de muchos nombres que indica su tipo habitual: `.txt`, `.java`. |
| Ruta | Dirección de un archivo o carpeta: `C:\EDE\notas.txt` en Windows. |
| Aplicación | Programa que utilizamos para una tarea: un editor de texto. |
| Lenguaje de programación | Notación con reglas para expresar programas: Java o C. |

## 1. LOS PROGRAMAS Y EL EQUIPO QUE LOS EJECUTA

### 1.1. Hardware y software

El **hardware** son los componentes físicos de un sistema informático: procesador, memoria, unidades de almacenamiento, teclado o pantalla. El **software** comprende los programas y los elementos asociados, como datos y documentación. Un programa contiene instrucciones para realizar una tarea.

Podemos distinguir, de forma general, **software de sistema**, como el sistema operativo y los controladores de dispositivos, y **software de aplicación**, como un navegador o un editor. El sistema operativo gestiona recursos y ofrece servicios a las aplicaciones. Los controladores permiten trabajar con dispositivos concretos.

Por ejemplo, un editor solicita guardar un documento; el sistema operativo gestiona el acceso al almacenamiento. El editor no necesita conocer todos los detalles de cada modelo de SSD. Esta colaboración entre capas permite utilizar distintos programas sobre un mismo equipo.

### 1.2. Procesador, memoria, almacenamiento y periféricos

Imaginad una calculadora: escribís dos números, pulsáis un botón y aparece el resultado. Aunque la operación sea sencilla, intervienen varios componentes:

| Componente | Función | En la calculadora |
|---|---|---|
| **Procesador o CPU** | Ejecuta instrucciones máquina y realiza operaciones. | Ejecuta las instrucciones que procesan los números y calculan el resultado. |
| **Memoria RAM** | Mantiene temporalmente código y datos necesarios durante la ejecución. Es volátil. | Contiene datos de trabajo, como los números y el resultado. |
| **Almacenamiento: SSD o disco duro** | Conserva archivos aunque apaguemos el equipo. Es no volátil. | Guarda los archivos de la aplicación y, si se guarda, su historial. |
| **Periféricos de entrada** | Introducen información. | El teclado o el ratón permiten indicar la operación. |
| **Periféricos de salida** | Presentan resultados. | La pantalla muestra el resultado. |

Hay dispositivos que combinan entrada y salida, como una pantalla táctil. Una tarjeta de red permite enviar y recibir información de otros equipos. Un programa puede utilizar unos dispositivos u otros según su finalidad.

**RAM y almacenamiento no son intercambiables.** Al cerrar una aplicación se liberan sus recursos de memoria, pero sus archivos guardados permanecen en el almacenamiento. Un resultado que solo existía en memoria puede perderse si el programa termina sin guardarlo.

Tampoco basta con decir «el ordenador tiene mucha memoria». Un equipo puede tener un SSD con mucho espacio y poca RAM disponible para trabajar con varias aplicaciones. Son recursos diferentes.

### 1.3. Del programa guardado al proceso en ejecución

Un **programa** puede estar almacenado sin ejecutarse. Un **proceso** es una instancia en ejecución, con su estado y los recursos que el sistema operativo le asigna.

En un modelo simplificado, al abrir una aplicación sucede lo siguiente:

1. El sistema operativo prepara el proceso y carga en memoria las partes necesarias del programa y sus datos.
2. La CPU ejecuta instrucciones; el sistema operativo reparte el tiempo de ejecución entre los procesos.
3. El programa recibe datos, realiza operaciones y puede solicitar acceso a archivos o dispositivos.
4. Al terminar el proceso, se liberan sus recursos. Los datos guardados en archivos permanecen.

![Ciclo de vida de un proceso](/img/UP01/process-lifecycle.gif)

No tiene por qué cargarse todo el programa de golpe. Además, una aplicación puede utilizar varios procesos. En esta unidad basta con distinguir **el programa guardado** de **su ejecución y estado en memoria**.

**Ejemplo resuelto:** cerramos un editor después de guardar `notas.txt`. Termina su proceso y se libera la memoria que utilizaba; el archivo continúa en el disco. Si abrimos el editor de nuevo, se inicia una nueva ejecución que puede leer ese archivo.

## 2. DEL CÓDIGO FUENTE AL EJECUTABLE

### 2.1. Lenguaje y código fuente

El **código fuente** es la representación del programa escrita en un lenguaje de programación. Habitualmente se guarda como texto que podemos leer y editar. El lenguaje establece reglas de escritura y significado; no es el editor con el que lo escribimos.

Por ejemplo, `Hola.java` puede contener código Java y abrirse con distintos editores. IntelliJ IDEA ayuda a trabajar con ese código, pero no es el lenguaje Java. El mismo razonamiento se aplica a C y CLion.

Este podría ser el contenido de `Hola.java`:

```java
public class Hola {
    public static void main(String[] args) {
        System.out.println("Hola, mundo");
    }
}
```

En general, salvo en los lenguajes interpretados, el **código fuente no se ejecuta directamente**. La CPU no entiende instrucciones de alto nivel como `System.out.println`, `while` o `class`.  

La CPU solo ejecuta **código máquina**, es decir, instrucciones binarias específicas de una arquitectura. Por eso siempre necesitamos **un proceso de traducción** (compilación) o **un programa que ejecute el código** (intérprete o máquina virtual) para convertir esas instrucciones de alto nivel en operaciones que la CPU sí puede ejecutar.

### 2.2. Compilación, código objeto y enlazado

Un **compilador** traduce código de un lenguaje a otra representación. Su resultado puede ser código máquina, ensamblador o código intermedio: compilar no significa siempre obtener directamente un `.exe`.

Para distinguir fuente, objeto y ejecutable, tomaremos como referencia un proceso habitual de construcción de programas C:

| Representación | Qué contiene | Ejemplo |
|---|---|---|
| **Código fuente** | Instrucciones legibles y editables escritas por el programador. | `hola.c` |
| **Código objeto** | Resultado de la traducción, normalmente con instrucciones máquina e información pendiente de resolver en el enlazado. | `hola.o` o `hola.obj` |
| **Código ejecutable** | Programa preparado para que el sistema operativo lo cargue y lo inicie en la plataforma correspondiente. | `hola.exe` en Windows, o `hola` en Linux. |

El **enlazador**, o *linker*, combina archivos objeto y resuelve referencias entre ellos y las bibliotecas necesarias. Una **biblioteca** reúne código reutilizable, por ejemplo para operaciones de entrada y salida.

```text
hola.c ── traducción ──► hola.o ── enlazado ──► ejecutable
                                    ▲
                        otros objetos y bibliotecas
```

En herramientas como GCC, la construcción puede incluir preprocesamiento, compilación, ensamblado y enlazado. Aquí agrupamos las primeras etapas para centrarnos en los archivos que obtenemos. GCC permite detenerse antes del enlazado con `-c`. [Documentación de GCC](https://gcc.gnu.org/onlinedocs/gcc/Overall-Options.html).

Un archivo objeto de este proceso **no se inicia como una aplicación independiente**. Renombrarlo a `.exe` no resuelve sus referencias pendientes. Un ejecutable tampoco tiene por qué incluirlo todo: puede necesitar bibliotecas compartidas o archivos externos.

Estos nombres describen funciones y formatos, no solo extensiones. En Linux un ejecutable no necesita terminar en `.exe`, pero debe tener un formato adecuado y los permisos necesarios para ejecutarlo.

### 2.3. Ejemplo guiado en C

Este programa muestra un saludo. No necesitáis dominar su sintaxis: observad la relación entre el texto inicial y los archivos generados.

**Archivo `hola.c`:**

```c
#include <stdio.h>

int main(void) {
    puts("Hola, mundo");
    return 0;
}
```

En una terminal de Windows con GCC ya configurado, podemos separar la generación del objeto y del ejecutable:

```powershell
gcc -c hola.c -o hola.o
gcc hola.o -o hola.exe
.\hola.exe
```

| Paso | Qué debemos observar |
|---|---|
| Primer comando | Se genera `hola.o` sin realizar todavía el enlazado final. |
| Segundo comando | Se realiza el enlazado y se obtiene `hola.exe`. |
| Tercer comando | Se inicia el ejecutable y aparece `Hola, mundo`. |

El parámetro `-o` indica el nombre del archivo de salida. Los comandos se ejecutan desde la carpeta del ejemplo. Son una demostración del proceso, no una tarea de instalación: en UP02 prepararemos los entornos.

**Para pensar:** si cambiamos el saludo en `hola.c` y ejecutamos el antiguo `hola.exe` sin reconstruirlo, veremos el saludo anterior. Editar el fuente no modifica automáticamente el ejecutable que ya existía.

## 3. CÓDIGO INTERMEDIO Y MÁQUINAS VIRTUALES

### 3.1. El recorrido de un programa Java

Otra posibilidad es traducir el código fuente a una representación que ejecuta un entorno específico. En el recorrido habitual de Java, el compilador **`javac`** genera archivos **`.class`**, que contienen **bytecode** e información adicional.

El bytecode es **código intermedio**: ya no es el texto fuente Java, pero sus instrucciones están destinadas a la **máquina virtual de Java**, o **JVM**, no directamente a la CPU de vuestro equipo.

```text
Hola.java ── javac ──► Hola.class ── JVM ──► ejecución en el equipo
  fuente                bytecode
```

Una implementación de la JVM puede interpretar instrucciones de bytecode y compilar partes a código máquina durante la ejecución. Esta última técnica se denomina **compilación JIT**, del inglés *Just-In-Time*. La CPU sigue ejecutando instrucciones máquina: la JVM proporciona la capa que permite ejecutar el programa a partir del bytecode. [Especificación de la JVM](https://docs.oracle.com/javase/specs/jvms/se25/html/jvms-1.html).

La JVM no equivale a instalar un ordenador completo con otro sistema operativo. Es una máquina virtual orientada a ejecutar programas. Tampoco debe confundirse `Hola.class` con el archivo objeto nativo `hola.o` del ejemplo anterior: sus formatos y destinos de ejecución son diferentes.

### 3.2. Demostración guiada: Hola Mundo

Observad este archivo **`Hola.java`**:

```java
public class Hola {
    public static void main(String[] args) {
        System.out.println("Hola, mundo");
    }
}
```

Por ahora, fijaos en tres elementos: el nombre `Hola`, el método `main`, que sirve como punto de entrada en este ejemplo, y la instrucción que muestra el saludo. Estudiaremos clases y objetos más adelante.

En una terminal situada en la carpeta del archivo, con un JDK configurado, realizamos dos acciones:

```text
javac Hola.java
java Hola
```

**Primera acción: compilar.** `javac` lee el fuente y genera `Hola.class` si no encuentra errores que impidan la compilación. En este ejemplo sencillo aparece un archivo de clase; otros programas pueden generar varios. [Comando javac](https://docs.oracle.com/en/java/javase/25/docs/specs/man/javac.html).

**Segunda acción: ejecutar.** `java Hola` inicia la ejecución de la clase `Hola` mediante la JVM. En este comando escribimos el nombre de la clase, sin `.class`. El resultado esperado es:

```text
Hola, mundo
```

Java dispone de otras formas de lanzamiento, pero aquí separamos deliberadamente compilación y ejecución para reconocer qué ocurre en cada paso. [Comando java](https://docs.oracle.com/en/java/javase/25/docs/specs/man/java.html).

| Elemento observado | Qué representa |
|---|---|
| `Hola.java` | Fuente que podemos modificar con un editor. |
| `javac` | Compilador de Java. |
| `Hola.class` | Archivo binario con bytecode y datos para la JVM. |
| `java Hola` | Orden para iniciar el programa del ejemplo. |
| JVM | Entorno que carga y ejecuta ese código. |
| `Hola, mundo` | Salida producida por la ejecución, no un nuevo tipo de código. |

Abrir un `.class` con un editor de texto no muestra el fuente original como si fuera un `.java`. Existen herramientas para inspeccionarlo, pero no son necesarias para entender este recorrido.

**Ejemplo resuelto:** modificamos el mensaje en `Hola.java`, guardamos y ejecutamos `java Hola` sin volver a compilar. Se utiliza el `.class` anterior. Para observar el nuevo mensaje en este procedimiento hay que repetir `javac Hola.java` y después `java Hola`.

### 3.3. Portabilidad y entorno de ejecución

La **portabilidad** es la posibilidad de utilizar un programa en diferentes plataformas con pocos cambios. Un ejecutable nativo se construye para una plataforma concreta: intervienen la arquitectura del procesador, el sistema operativo y sus dependencias.

En Java, un mismo archivo `.class` puede utilizarse en distintos sistemas si disponen de un entorno compatible. Cada sistema necesita su propia implementación de la JVM. Deben ser compatibles también la versión del bytecode y las bibliotecas utilizadas; acceder a una ruta exclusiva de Windows, por ejemplo, puede limitar la portabilidad del programa.

El **JDK** (*Java Development Kit*) reúne herramientas para desarrollar en Java, incluido `javac`, y lo necesario para ejecutar los ejemplos. **JRE** (*Java Runtime Environment*) designa el entorno de ejecución, con la JVM y bibliotecas, sin las herramientas de desarrollo. No necesitáis instalar JDK y JRE por separado para esta demostración: utilizaremos un JDK en UP02.

> [!NOTE]
> Distinguid las funciones: el **IDE** ayuda a trabajar con el proyecto; el **compilador** traduce el código; la **JVM** ejecuta el bytecode. Pulsar un botón del IDE puede activar varias herramientas, pero no las convierte en la misma cosa.

## 4. CÓMO CLASIFICAMOS LOS LENGUAJES

Clasificar un lenguaje consiste en describirlo desde distintos puntos de vista. «Alto nivel», «orientado a objetos» y «propósito general» no son opciones excluyentes: responden a preguntas diferentes.

### 4.1. Por nivel de abstracción

La **abstracción** permite trabajar sin tener que expresar todos los detalles de la máquina.

- **Lenguaje máquina:** codifica instrucciones para una arquitectura de procesador. Es lo que la CPU ejecuta directamente.
- **Ensamblador:** representa instrucciones mediante nombres simbólicos, como `MOV` o `ADD`, según la arquitectura. Una herramienta llamada **ensamblador** las traduce. Es un lenguaje de **bajo nivel**, próximo a la máquina.
- **Lenguajes de alto nivel:** permiten expresar operaciones con estructuras más alejadas de las instrucciones individuales de la CPU. Ejemplos: C, Java y Python.

C permite controlar detalles de memoria, pero se clasifica habitualmente como lenguaje de alto nivel. Tener mayor abstracción facilita expresar soluciones y puede favorecer la portabilidad; no garantiza por sí solo que cualquier programa funcione en todas las plataformas.

No necesitáis memorizar una clasificación histórica por generaciones. Debéis reconocer la diferencia entre escribir instrucciones ligadas a una arquitectura y expresar una solución mediante construcciones de alto nivel.

### 4.2. Por su forma habitual de ejecución

Hemos visto dos recorridos concretos. Añadimos la **interpretación**, en la que un programa intérprete realiza las operaciones descritas por el código o por una representación interna de este.

| Modelo habitual | Idea principal | Ejemplo orientativo |
|---|---|---|
| Compilación nativa previa | Se prepara código máquina para la plataforma antes de ejecutar el programa. | C con GCC, como en el ejemplo. |
| Interpretación | Un intérprete ejecuta el programa; puede realizar previamente transformaciones internas. | Python con CPython. |
| Compilación a código intermedio | Se obtiene código para un entorno de ejecución, que puede interpretarlo o compilarlo durante la ejecución. | Java con `javac` y una JVM. |

Estas categorías describen **implementaciones y recorridos habituales**, no propiedades exclusivas e inmutables de cada lenguaje. Se pueden combinar técnicas. Llamamos a menudo «híbrido» al modelo que combina compilación a código intermedio con interpretación o JIT.

Por ejemplo, **CPython**, la implementación más extendida de Python, compila el fuente a bytecode que ejecuta su intérprete. Por eso sería incorrecto afirmar que Python nunca compila o que siempre ejecuta el texto «línea por línea». Su bytecode tampoco es el bytecode de la JVM. [Glosario de Python: bytecode](https://docs.python.org/3/glossary.html#term-bytecode).

La velocidad y la portabilidad dependen de la implementación, el programa y el entorno. No se deducen únicamente de la etiqueta «compilado» o «interpretado».

### 4.3. Por paradigma

Un **paradigma** es una forma de organizar y expresar la solución. Muchos lenguajes son **multiparadigma**: permiten emplear varios enfoques. Aquí necesitamos reconocer las ideas, sin dominar todavía la sintaxis.

**Programación imperativa y procedimental.** Describimos pasos que modifican el estado del programa: asignar un valor, repetir una operación, acumular un resultado. En el enfoque procedimental agrupamos operaciones en procedimientos o funciones. La programación estructurada organiza el control mediante secuencia, selección y repetición.

Por ejemplo, para calcular un total podemos indicar «empezar en cero, recorrer los precios y sumar cada uno al acumulador». C es un ejemplo habitual de programación procedimental; también podemos escribir así en otros lenguajes.

**Programación orientada a objetos (POO).** Organizamos el programa mediante objetos que reúnen datos y comportamiento. Una clase `Reserva` puede describir objetos con una fecha y un titular, y una operación para cancelar. Una reserva concreta es un objeto de esa clase. Java ofrece un soporte central a este paradigma. Sus principios y su diseño se desarrollarán en UD7.

**Programación declarativa.** Expresamos el resultado deseado sin detallar todos los pasos para obtenerlo. Una consulta SQL permite pedir las tutorías de un profesor; el sistema de bases de datos decide cómo acceder a la información:

```sql
SELECT hora FROM tutorias WHERE profesor = 'Ana';
```

Suponemos que existe una tabla `tutorias` con esas columnas. La consulta describe qué filas y dato queremos recuperar, sin escribir el recorrido de almacenamiento. [Consultas en PostgreSQL](https://www.postgresql.org/docs/current/tutorial-select.html).

Dentro de los enfoques habitualmente asociados a lo declarativo encontramos:

- **Programación funcional:** expresa cálculos mediante funciones y su composición, favoreciendo evitar cambios de estado y efectos secundarios. Haskell es un ejemplo; Python y Java también incorporan recursos funcionales.
- **Programación lógica:** expresa hechos y reglas a partir de los cuales se realizan consultas. Prolog es un ejemplo. Podemos declarar relaciones familiares y reglas para preguntar quién es abuelo de quién.

**Comparación resuelta en Python:** queremos sumar `2`, `4` y `6`.

```python
numeros = [2, 4, 6]
total = 0
for numero in numeros:
    total = total + numero
print(total)
```

Este fragmento muestra explícitamente los pasos y el cambio de `total`. Podemos expresar la misma petición de forma más declarativa utilizando una operación ya disponible:

```python
numeros = [2, 4, 6]
total = sum(numeros)
print(total)
```

Ambos muestran `12`. El segundo oculta el recorrido dentro de una operación; no convierte por ello todo Python en un lenguaje puramente funcional. Un ejemplo de código y la clasificación completa del lenguaje son niveles distintos.

### 4.4. Por propósito

Los lenguajes de **propósito general** permiten resolver problemas en ámbitos variados: aplicaciones de gestión, cálculo, servicios, etc. Java, Python y C pertenecen a esta categoría.

Los lenguajes de **dominio específico**, o **DSL**, se orientan a un ámbito concreto. SQL está especializado en trabajar con datos. Ser específico no significa necesariamente ser más sencillo o menos potente: indica que el lenguaje se centra en un tipo de problema.

También encontraréis lenguajes de marcado, como HTML, y de estilos, como CSS. Conviene reconocer su función y distinguirlos de los lenguajes de programación de propósito general.

### 4.5. Una clasificación conjunta

| Lenguaje | Nivel | Paradigmas o enfoques destacados | Propósito |
|---|---|---|---|
| C | Alto nivel, con acceso a detalles de memoria. | Imperativo y procedimental. | General. |
| Java | Alto nivel. | Orientado a objetos e imperativo; también permite recursos funcionales. | General. |
| Python | Alto nivel. | Multiparadigma: imperativo, orientado a objetos y recursos funcionales. | General. |
| SQL | Alto nivel. | Declarativo, especialmente en las consultas. | Específico: datos. |
| Ensamblador de una arquitectura | Bajo nivel. | Imperativo, próximo a las instrucciones de la máquina. | Ligado a una arquitectura, no a una única aplicación. |

**Ejemplo de respuesta razonada:** «Java es de alto nivel porque no escribimos directamente instrucciones de una CPU; es de propósito general porque sirve para aplicaciones de ámbitos distintos; ofrece orientación a objetos y normalmente lo compilamos a bytecode para una JVM».

Reconocer estas dimensiones resulta más útil que memorizar una única etiqueta por lenguaje. Un lenguaje puede servir para varios estilos, y distintos lenguajes pueden compartir una forma de ejecución.

<details>
<summary>Ver soluciones de las prácticas y del refuerzo</summary>

**A. Ejecución.** El teclado introduce el nombre y la pantalla lo presenta. La CPU ejecuta las instrucciones del editor; la RAM mantiene su estado y datos de trabajo; el almacenamiento conserva `nombre.txt` al guardarlo. Cerrar el proceso libera sus recursos. Un cambio que solo existía en memoria y no se guardó ni se recuperó automáticamente se pierde.

**B. Archivos.** `hola.c` y `Hola.java` son fuentes. `hola.o` es el objeto nativo; `hola.exe`, el ejecutable nativo; `Hola.class` contiene bytecode para la JVM. En C, la traducción produce el objeto y el enlazado prepara el ejecutable; en Java, `javac` produce el `.class` y la JVM lo ejecuta. Editar el fuente no reconstruye los archivos ya generados.

Copiar el `.exe` a Linux no garantiza su ejecución directa: se construyó para otra plataforma. El `.class` puede utilizarse con un entorno Java compatible, siempre que también estén disponibles sus dependencias y no existan otras restricciones del programa.

**C. Clasificación.** C: alto nivel, imperativo/procedimental y general. Java: alto nivel, orientación a objetos con otros recursos y general. SQL: alto nivel, declarativo y específico para datos. Java se compila a una representación que ejecuta la JVM; compilación y máquina virtual son compatibles.

**Refuerzo.** Un esquema posible es:

```text
SOFTWARE: programas que utilizan los recursos del HARDWARE

C:     fuente → traducción → objeto → enlazador → ejecutable nativo
Java:  fuente → compilador → bytecode → máquina virtual

En ambos casos, durante la ejecución intervienen:
CPU: ejecuta instrucciones máquina
RAM: mantiene código y datos de trabajo
Almacenamiento: conserva archivos
Periféricos: permiten intercambiar información
```

Podéis emplear otras disposiciones. Comprobad que objeto nativo y bytecode no aparezcan como sinónimos y que la máquina virtual no sustituya al hardware físico.
